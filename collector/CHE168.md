# Che168 API collector

Сборщик che168 внутри пакета `collector`. Получает список через мобильный API, загружает полную карточку
каждого найденного автомобиля и отдаёт записи `carlot/1`. Работает без браузера. Два способа запуска:

- **из админки** — задача в `parse_jobs`, её берёт `collector serve`, лоты идут в буфер приёма и в `lots`
  (раздел [Из админки](#из-админки-collector-serve));
- **из командной строки** — ограниченный сбор в файлы (JSONL), без БД (раздел [Запуск](#запуск)).

Реально проверены 10 страниц и 197 полных карточек с продолжением и четырьмя плановыми ротациями,
а также отдельный сетевой запуск из Linux-контейнера: [результаты проверки](CHE168-VALIDATION.md).

## Запуск

Из каталога `collector`:

```powershell
uv sync --extra che168
uv run --extra che168 python -m collector.che168 --env-file ../.env --output ../analysis/che168/runs/first --max-pages 10 --max-cars 200
```

Если `uv` не находится в PATH, подготовленное окружение этой рабочей копии позволяет запускать
`.venv/Scripts/python.exe -m collector.che168` с теми же аргументами.

Нужны `FLOPPY_USERNAME`, `FLOPPY_PASSWORD`, `FLOPPY_HOST` в окружении процесса.
`--env-file` необязателен: это явно выбранный локальный файл; уже заданные переменные окружения важнее.
Не передавайте пароль в аргументах команды. Прокси всегда запрашивается для CN.

Продолжение того же сбора:

```powershell
uv run --extra che168 python -m collector.che168 --env-file ../.env --output ../analysis/che168/runs/first --resume --max-pages 10 --max-cars 200
```

`--max-pages` — максимальный номер страницы от начала сбора, `--max-cars` — общее число сохранённых
карточек в этом каталоге, включая предыдущие запуски. Для увеличения объёма укажите большие лимиты.
Увеличение лимитов не требует нового каталога. Менять размер страницы, версию маппинга или профиль подписи
при продолжении нельзя: коллектор проверяет совместимость сохранённого состояния.
Лимиты меньше уже сохранённого прогресса отклоняются.

## Ротация и лимиты

| Параметр | По умолчанию | Значение |
|---|---:|---|
| `--pagesize` | 20 | Размер запрашиваемой выдачи, 1–20 |
| `--max-pages` | 10 | Максимальный номер страницы |
| `--max-cars` | 200 | Максимальное общее число записанных карточек |
| `--delay` | 3 | Минимальная пауза после запроса, секунды; минимум 1 |
| `--rotate-every-pages` | 2 | Новая прокси-сессия перед страницами 3, 5, 7…; 1 — после каждой; 0 — выключить плановую смену |
| `--max-rotations` | 8 | Общий предел смен сессии за запуск, включая плановые |
| `--max-challenge-rotations` | 3 | Из общего предела: максимум смен из-за CAPTCHA/403/redirect |
| `--max-requests` | 500 | Все API-попытки, включая неудачные и повторы, за текущий запуск |
| `--max-seconds` | 1800 | Временной бюджет запуска; начатый запрос может занять ещё до 30 с |

Механизм аналогичен `ProxyPool.refresh` в Encar: меняется `session` в имени пользователя FloppyData.
В che168 при смене дополнительно создаётся новый HTTP-клиент, чтобы сбросить соединения и cookies.
Регион остаётся CN. Новый session ID запрашивает новую сессию, но сам по себе не доказывает новый выходной IP.

Плановая смена выполняется после обработки карточек двух страниц, перед следующим списком. CAPTCHA,
EdgeOne, HTTP 403 или перенаправление запускают ограниченную смену сессии и повтор **того же запроса**.
Счётчик страницы не продвигается, уже сохранённые машины повторно не загружаются.
Лимит смен исчерпан — прогресс сохраняется, процесс завершается с ошибкой. Чтобы отключить реактивную смену,
укажите `--max-challenge-rotations 0`.

HTTP 429, ошибки авторизации прокси и ошибка подписи API не запускают ротацию: они сохраняются как отдельные
причины остановки. При сетевой ошибке или HTTP 500/502/503/504 разрешён один повтор в текущей сессии.
Все повторы учитываются в бюджете запросов. Каждый запуск `--resume` открывает новую сессию;
ротационные и временные бюджеты относятся к текущему запуску.

## Результат и сохранность

В каталоге результата:

- `state.sqlite3` — очередь ID, страницы и готовые записи; это локальная SQLite, не БД приложения.
- `cars.jsonl` — выгрузка готовых `carlot/1`, обновляется атомарной заменой при завершении/обработанной ошибке.
- `summary.json` — причина завершения, число страниц/машин, остаток очереди, количество запросов и ротаций.
- `writer-lock.sqlite3` — блокировка второго процесса, пытающегося писать в тот же каталог.

Сначала атомарно сохраняются ID страницы и номер следующей. Затем каждая карточка фиксируется отдельной
транзакцией. После сбоя сначала обрабатываются оставшиеся ID, затем загружается следующая страница.
Повторы ID между страницами объединяются. Повтор страницы без новых ID останавливает сбор с диагностикой.

Ctrl+C/SIGTERM завершает текущую операцию и сохраняет выгрузку. При жёстком завершении процесса SQLite
сохраняет зафиксированные записи; JSONL может отставать до следующего `--resume`.
Каталоги живых результатов в `analysis/che168/runs/` исключены из Git.

Код возврата 0 означает достижение заданного лимита или конца API, **не полный обход площадки**.
Код 1 — ошибка/блокировка/исчерпание бюджета, 2 — параметры/зависимости, 130 — прерывание.
`summary.full_run` всегда false: эти результаты нельзя использовать для снятия объявлений с продажи.

## Данные

Цена переводится из 万 юаней в целые CNY (12,68 → 126800), пробег из 万 км в километры (0,8 → 8000),
через Decimal без округления. Неизвестная или некорректная обязательная цена/пробег останавливает сбор,
а не превращается в ноль. У `extra.price_unit` явное значение `CNY_yuan`.

Названия марки и модели берутся из `brandname` и `seriesname`. Двигатель — только из явно указанного
объёма; неизвестное значение любого поля остаётся пустым. Дата регистрации с точностью до месяца
остаётся в `extra.che168.firstregdate`; день не выдумывается. Число переоформлений не выдаётся за число владельцев.

| Поле CarLot | Из Che168 | Правило |
|---|---|---|
| `year` | `carname` | Год модели, который Che168 пишет как `2018款`; не год регистрации |
| `fuel` | `fuelname` | `插电混动`, `增程式` → plugin_hybrid; `汽油+48V轻混系统` → gasoline (мягкий гибрид не едет на электричестве) |
| `drive_type` | `drivingmode` | `…四驱` (включая `双电机四驱`) → awd: Che168 не отличает постоянный полный привод от подключаемого |
| `body_type` | `levelname` | Только по слову класса: SUV, MPV → minivan, `跑车` → coupe, `皮卡` → pickup. «中型车» кузов не называет — пусто |
| `color` | `colorname` | Группа Che168 остаётся группой: `银/灰色` → `Silver/Gray`; неизвестный цвет — как прислал Che168 |
| `listing.listed_at` | `publicdate` | Дата или «今天/昨天/N天前» от дня наблюдения; полночь по Китаю (UTC+8) |
| `listing.location` | `cname` | Город как прислал Che168 |
| `listing.retail_value` | `guidanceprice` | Цена нового авто: 万 CNY → целые CNY; `0` — неизвестно, пусто |

`cid`, `pid`, `countyname`, `carusename`, `isnewcar`, `environmental`, `flowmode`, `firstregstr`,
`isev`, `batterypower`, `lifemileage`, `cartype` сохраняются в `extra.che168` без маппинга. На 30 живых карточках
2026-10-30 `carusename` везде `家用` (личное использование); коммерческое (`营运`) ещё не встречалось, поэтому
в `sell_type` не переносится.

Проверка на 197 карточках прогона 2026-10-29: год 197, топливо 194, привод 194, кузов 103, цвет 197, дата объявления 197.
Версия маппинга в отпечатке состояния — 2: каталог, собранный версией 1, не продолжается через `--resume`.

Сохраняются URL фотографий; сами изображения не скачиваются. Телефоны продавцов, VIN, cookies,
пароли и свободный текст продавца в результат не входят. `extra.che168` хранит разрешённый набор
исходных автомобильных полей. В файловом режиме правила отбора не применяются (`selection_evaluated=false`);
в `collector serve` применяются — раздел ниже.

## Из админки (collector serve)

Админка → площадка Che168 → «Запустить парсинг»: «Сбор свежих объявлений» или «Тестовый (5 страниц)».
Задачу берёт `collector serve`, у которого в `COLLECTOR_SOURCES` есть `che168` (`adapters/che168/job.py`):

- как у Encar, запросы идут параллельно: `CHE168_LIST_WORKERS` прокси-сессий (4) читают страницы общей выдачи
  (по 20 машин) волной — по странице на сессию, на волну вперёд от воркеров; карточки разбирают `CHE168_WORKERS`
  воркеров (4). У каждой сессии свой выходной IP CN FloppyData, cookies и пауза `CHE168_DELAY` (3 с), поэтому каждый
  IP ходит так же редко, как одна сессия, а машин в минуту в N раз больше;
- как история Encar (`lot_history`), карточки хранятся в `collector.lot_history` (source `che168`): только то, что
  читает маппинг, плюс факты списка — цена, пробег, число фото. Машина, у которой эти факты не изменились, а карточка
  моложе `CHE168_CARD_MAX_AGE_HOURS` (168), пишется из хранилища без запроса; новые и изменившиеся машины качаются.
  Повторный прогон упирается в чтение списка, а не в карточки. Строку хранилища удаляет purge `lots:lifecycle`;
- лимиты — `CHE168_MAX_PAGES` (20) и `CHE168_MAX_CARS` (400), `filters.max_pages` / `max_cars` задачи важнее;
  предел времени `CHE168_MAX_HOURS` (6 ч); лимит запросов прогона общий на все сессии;
- плановая смена сессии: у сессии списка — после каждых 2 своих страниц, у воркера — каждые 40 карточек; CAPTCHA, 403 или redirect
  меняют сессию только тому воркеру, который их получил (не больше 3 раз на сессию);
- ответ дольше 10 с (таймаут, ошибка прокси) — зависший выход прокси: запрос повторяется через новую сессию,
  не больше 2 раз, как у Encar (`COLLECTOR_HTTP_TIMEOUT`). Обычный ответ che168 — 0,4–3 с; в прогоне 30 при
  таймауте 30 с два зависших выхода тормозили свои воркеры по 30–60 с, остальные отвечали за 0,4–0,7 с;
- записи по 10 уходят в `collector.ingest_lots`, после каждой пачки — чекпоинт в `parse_jobs.progress`: следующая
  страница и все машины из списка, которых ещё нет в буфере (в очереди и в работе у воркеров). По SIGTERM задача
  возвращается `interrupted`, следующий процесс продолжает и не грузит записанные карточки снова;
- лог задачи — строка на страницу: `page 3/20: 20 listed, 20 new · 57 cars, 9.8 cars/min, 0 skipped · 61 requests,
  2.2 s per answer, 4 sessions · proxy 4.1 MB · 1 rotations, 0 challenges, 0 retries`; в админке у прогона заполнены
  «Прокси» и «Длительность», под «Записано в базу» — сколько машин ещё ждут приёма;
- карточку, которую API не отдал (машину успели продать) или маппинг не прочитал, пропускаем;
  пять таких подряд останавливают прогон с ошибкой; CAPTCHA, 403, 429 — как в файловом режиме;
- правила отбора (`parse_filters`) — как у Encar: ранний проход по году и пробегу из строки списка отсеивает
  машину без запроса карточки (новая машина не пишется: её нет в `lots`; машина из хранилища уходит с вердиктом),
  полная проверка PRE, затем POST — после карточки; вердикт в лоте, ядро пишет `filter_skip_log` и держит
  отсеянное вне `lots`. Правила без площадки по цене, стоимости ремонта и цене нового записаны в ₩ и к che168 не
  применяются (`che168_rules`); лимит в ¥ — правило площадки Che168;
- прогон che168 **никогда не полный** (`full_run=false`): `lots:lifecycle` по нему ничего не снимает.

Приём (`ingest:consume`) пишет лот в `lots` с `currency = CNY` и id `che168:<infoid>`, справочник ставит марку
и модель (`Che168Matcher`, поколение пусто). Мини-апп показывает che168 рядом с Encar: цена в ¥, фильтр цены в
валюте площадки, без корейского калькулятора.

### Отчёт осмотра Chaboshi

Примерно у трети машин (7 из 20 в выборке 31.10.2026) карточка ссылается на отчёт осмотра
Chaboshi (查博士, `cxc.reporturl`); флаг `isreport` при этом 0 — на него не смотрим. После опций воркер
открывает страницу отчёта (`api.chaboshi.cn`) и делает тот же запрос данных, что её собственный скрипт
(`app.chaboshi.cn/wap/insurance/getDetection{FuelVehicle|NewEnergy}ReportData`, параметры из
`window.__INIT_PARAMS__` страницы, ничего не подписываем сами). Браузер не нужен. Отчёты других сервисов
(Guazi и т. п.) не читаются.

- `adapters/che168/chaboshi.py` оставляет из отчёта вердикты (крупное ДТП, затопление, пожар — классификация
  Chaboshi), оценку, дату и пробег осмотра, замечания каждого раздела и непроверенные узлы, у электромобиля —
  SOH батареи с датой данных, тип, ёмкость, оценочный запас хода. VIN, телефон, инспектор, адрес, номера
  заказов и подписанные ссылки не сохраняются.
- В лоте это `inspection` (→ `lot_inspections`): `has_accident/has_flood/has_fire` — вердикты осмотра,
  `has_outer_damage` — замечания по кузову, всё остальное в `details.chaboshi`
  (пример — `contracts/fixtures/chaboshi_*.json`). **Это не страховая история:** `lots.has_accident`
  остаётся пустым, «Без ДТП» по осмотру не ставится.
- Отчёт хранится вместе с карточкой (`CARD_VERSION` 3: первый прогон после выкладки перекачает карточки).
  Отчёт, который не удалось получить, не останавливает машину: она пишется без него
  (`reports_failed`), следующий прогон берёт её карточку заново.
- Ядро описывает отчёт по-русски (`App\Catalog\Che168\ChaboshiReport`, словарь
  `resources/catalog/che168/chaboshi.json`, незнакомый термин — по-китайски), карточка мини-аппа показывает
  блоки «Осмотр Chaboshi» и «Батарея по осмотру».

Трафик: +2 запроса на машину с отчётом (~0,7 на машину в среднем), отчёт ~30–40 КБ.

### Railway

Сейчас (2026-10-30) che168 и Encar ведёт один сервис `collector` (в образе есть `curl_cffi`):

| Сервис | Переменные |
|---|---|
| collector | `COLLECTOR_SOURCES=encar,che168`; при желании `CHE168_WORKERS`, `CHE168_LIST_WORKERS`, `CHE168_DELAY`, `CHE168_CARD_MAX_AGE_HOURS`, `CHE168_MAX_*` |
| web (Laravel) | `PARSER_SOURCES=encar,che168` — площадка появляется в админке, мини-аппе и фильтрах |

Один процесс ведёт одну задачу: пока идёт прогон che168, задача Encar ждёт в очереди, и наоборот. Если длинные
сборы che168 начнут задерживать Encar, che168 выносится в отдельный сервис из того же репозитория (Root Directory
`collector`, Dockerfile) с `COLLECTOR_SOURCES=che168`, а у `collector` остаётся `encar`. Переменные нового сервиса —
ссылками на `collector` (`COLLECTOR_DATABASE_URL=${{collector.COLLECTOR_DATABASE_URL}}`, `FLOPPY_*` — на
`carbotacrchi`); вставлять их в сам `collector` нельзя: ссылка на себя даёт пустое значение. Пока идёт любой прогон,
почасовой `lots:lifecycle` пропускает запуск.

Прокси для che168 всегда CN (`FLOPPY_*` общие с Encar). Миграция `2026_10_30_000001_add_currency_to_lots`
добавляет колонку мгновенно, данные не переписывает.

## Linux / Railway (файловый режим)

Отдельный образ не меняет действующий образ Encar:

```bash
docker build -f Dockerfile.che168 -t carbot-che168 .
```

Для реального запуска передайте только необходимые `FLOPPY_*` переменные и подключите постоянный каталог
к `/data/che168`, доступный для записи UID 10001. Процесс выполняет один ограниченный запуск и завершается.
При повторном запуске существующего каталога явно задайте `--resume`. Не включайте бесконечный restart-loop
для заблокированного запуска: он сбросит бюджеты попыток.

Что ещё не сделано: опции che168, снятие проданных машин che168 (нужен способ понять, что объявление снято, —
сейчас такие лоты остаются активными), расписание сборов (`parser_schedules`) для che168 не проверялось.

## Подпись и границы покрытия

В пакет включён небольшой `adapters/che168/signing-profile.json` с публичными параметрами JavaScript сайта,
URL исходного bundle и SHA256. Большой исследовательский JS-файл для запуска не нужен. Код сайта не исполняется.
При `signature_rejected` нужно проверить новую версию публичного frontend, обновить профиль и тесты;
автоматического скачивания и принятия неизвестного алгоритма нет.

Текущий поиск — общий мобильный список по Китаю, без фильтров марки/года. Коллектор сохраняет `carlist`;
рекламные и рекомендательные блоки `otherlist` не считаются обычными страницами автомобилей.
Короткий `carlist` не означает конец: используются `pageindex` и `pagecount`. Совпадение этой выдачи со всем
каталогом сайта не доказано. Меняющаяся выдача при долгом обходе не является неизменным снимком каталога.
