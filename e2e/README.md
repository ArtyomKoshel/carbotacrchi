# UI-тесты (Playwright)

Тесты двух точек входа на локальном сервере поверх дампа прода:
- **мини-апп / сайт** (`/miniapp/`): поиск машин и фильтры (`tests/miniapp.spec.ts`);
- **админка** (`/admin`): пока не написаны.

Главная проверка — **фильтры не теряют машины**:
- модели марки в сумме дают все её машины;
- каждый выбор (модель → поколение → модификация → комплектация, «… не указано») показывает число машин,
  и поиск находит ровно столько же.

## Что нужно

1. Локальный стек `docker/dev` ([docs/local-stack.md](../docs/local-stack.md)): MySQL `127.0.0.1:3318`,
   база `carbot` — дамп прода. После выкатки справочника на дамп выполнить `php artisan catalog:remap`.
2. `laravel/.env`: `APP_ENV=local`, база — `carbot` на `127.0.0.1:3318`. При `APP_ENV=local` работает вход без Telegram
   (`laravel/routes/dev.php`), в остальных окружениях его нет.
   Тот же код уже открыт в стеке на http://localhost:8100 (несколько запросов параллельно) — тестам можно
   задать его вместо встроенного PHP-сервера на 8097.
3. Node 18+, один раз: `npm install` в этой папке. Используется Playwright 1.56.1 и браузер `chromium-1194`.
   Если браузера нет, его ставит `npx playwright install chromium`.

Сервер (`laravel/dev/router.php` на встроенном PHP-сервере, порт 8097) тесты поднимают сами. Если он уже запущен, используют его.

## Запуск

```
npm test                              # все тесты, без окна
npm run test:headed                   # видно окно браузера и все клики
E2E_SLOWMO=300 npm run test:headed    # то же медленнее, чтобы успевать следить
npm run test:ui                       # интерфейс Playwright: шаги, снимки, перезапуск отдельных тестов
npx playwright test -g "Kia"          # только тесты с «Kia» в названии
npm run report                        # отчёт последнего прогона
```

Работает один поток: встроенный PHP-сервер отвечает на один запрос за раз.

## Состояние (2026-10-25)

Проходят: вход без Telegram; модели Kia, BMW и Ford в сумме дают марку, и каждая находит своё число машин.

Остальное поправлено, но перед паузой ещё не перепроверено. Причиной падений была гонка в самом тесте: он ловил ответ
поиска от предыдущего изменения. Сейчас `shown()` перед каждым изменением ждёт, пока страница затихнет.
На экране мини-апп при этом показывал правильные числа.

Не написаны: тесты админки (вход через `/dev/admin-login`, список лотов с фильтром `?filters[make_model][ref_make_id]=…`,
карточка лота, раздел «Модель»), вид для телефона (там кнопка «Показать»).
