# 13 · Справочник (reference catalog)

> [← Field map](./12-field-map.md) · [Index](./index.md)

---

Собственный справочник автомобилей, не зависящий от площадки: **Марка → Модель → Поколение →
Модификация → Комплектация**. Площадка (сейчас Encar) только сопоставляется с ним, фильтры
работают по справочнику, а не по названиям Encar.

## Главное правило

**Ничего не додумываем.** Привод, топливо и поколение берутся только из того, что площадка
указала явно:

| Что | Откуда | Чего нет |
|---|---|---|
| Полный привод | xDrive, 4MATIC, quattro, ALL4, 4MOTION, AWD, «4» у Porsche, Dual Motor | «по умолчанию» для поколения, Turbo/GTS «обычно полноприводные» |
| Топливо | суффикс обозначения (520**d**, E300**e**, 320**i**), TDI/TFSI, P/D у Land Rover, модель целиком (i4 — электро) | «бензин, если не сказано иное» |
| Поколение | код кузова (G60, W213), номер поколения Encar («2세대», Gen 2), BadgeDetail («C7», «3세대») | год выпуска |

Неизвестное остаётся пустым: в карточке и фильтрах привода/топлива — собственные поля лота
от Encar. Вариант, где Encar не назвал поколение, уходит на ручную разметку.

Соглашения именования самого Encar можно записывать явно: модель без номера, у которой Encar
помечает только следующее поколение («Discovery Sport» / «Discovery Sport 2세대»), — первое
поколение. Такие соответствия лежат в `resources/catalog/encar/{make}.json` → `models`.

## Файлы

| Путь | Что |
|---|---|
| `resources/catalog/reference/{make}.json` | эталон: модели, поколения (код, номер, годы), комплектации, особые серии, слова двигателей (`engine`) |
| `resources/catalog/encar/tokens.json` | корейские слова бейджей → английские слова эталона |
| `resources/catalog/encar/{make}.json` | Encar → эталон: корейская марка, названия моделей (`names`), исключения (`models`, `badges`, `engine_prefix`, `words`) |
| `app/Catalog/Encar/EncarMatcher.php` | вариант Encar (корейские make, model, badge_group, badge, trim) → `VariantMatch` |
| `app/Catalog/BadgeGrammar.php` | общее для всех марок: кузов, места, особые серии, комплектация |
| `app/Catalog/Rules/*Rules.php` | обозначение двигателя: BMW, Mercedes, Audi, Porsche; остальные — `GenericRules` по `engine` из эталона |
| `app/Catalog/CatalogLinker.php` | варианты в `ref_variants`, лоты → `lots.ref_*` |

Encar читается только по собственным корейским полям, не по нашим переводам: переводы приходят
с опозданием (нормализация ждёт конца прогона) и устаревают, когда объявление меняет модель.

## Таблицы

| Таблица | Что |
|---|---|
| `ref_makes`, `ref_models`, `ref_generations`, `ref_complectations` | эталон (`catalog:remap` пишет его из JSON, ничего не удаляет) |
| `ref_modifications` | появляются, когда правила впервые читают вариант как эту модификацию |
| `ref_variants` | вариант площадки → место в справочнике, статус, `manual`, число активных лотов |
| `lots.ref_variant_id`, `ref_make_id` … `ref_complectation_id` | место лота, для фильтров (индексы — миграция `…000002`) |

Статусы варианта: `matched` — всё понятно, `no_engine` — понятно, но Encar не назвал двигатель,
`unmatched` — остались незнакомые слова или неизвестно поколение.

## Как лот попадает в справочник

- **При приёме** (`IngestConsumer`): записанные лоты связываются сразу; новый вариант читается
  правилами один раз. Ошибка связывания не держит буфер — лоты свяжет следующий `catalog:remap`.
- **`php artisan catalog:remap`** — после изменения эталона или правил: эталон в таблицы, все
  варианты читаются заново (кроме размеченных вручную), лоты переставляются порциями по PK.
  `--new-only` — читать только новые варианты.
- **Вручную**: админка → «Справочник: разбор» → «Разметить». Вариант больше не читается правилами,
  его лоты переезжают сразу. «Вернуть правилам» снимает ручную разметку.

## Как справочник обновляется

Ничего не пересоздаётся «с нуля» и ничего не удаляется: id в `ref_*` стабильны, лоты и подписки на них не теряются.

| Что меняется | Кто меняет | Что запустить |
|---|---|---|
| Эталон: модель, поколение, годы, комплектация (`reference/*.json`) | человек, через git | `catalog:validate`, затем `catalog:remap` |
| Корейские слова (`encar/tokens.json`), исключения Encar (`encar/{make}.json`) | человек, через git | `catalog:validate`, затем `catalog:remap` |
| Корейские названия моделей (`names`) | `catalog:encar-names --write` из лотов, где у Encar есть оба названия | `catalog:remap` |
| Модификации (`ref_modifications`) | сами, когда правила встречают новую | — |
| Новые варианты Encar | сами, при приёме лота | — |
| Ручная разметка | админка «Справочник: разбор» | — (сразу) |

## Проверка справочника

```bash
php artisan catalog:validate            # файлы + годы поколений против лотов
php artisan catalog:validate --no-data  # только файлы (для CI)
```

Файлы: коды и номера поколений уникальны в модели, годы по порядку, исключения Encar указывают
на существующие модель и поколение, фраза не одновременно комплектация и особая серия.

Данные: лоты, чей год не попадает в годы их поколения (±1). Год никогда не ставит лот в поколение,
поэтому это честная проверка — так нашлись ошибочные годы W205/X253 в эталоне, отсутствующие старые
поколения (Phantom VII, первый 500e) и ошибка сопоставления, когда правило «модель без номера —
первое поколение» перебивало код, который Encar указал. Остаются строки, где поколение назвал сам
Encar, а годы не сходятся (Passat B7 2016–2018): это данные Encar.

## Проверка покрытия

```bash
php artisan catalog:coverage --make=BMW          # по активным лотам базы
php artisan catalog:coverage --make=BMW --tree   # дерево модель → поколение → модификация → комплектация
```

Покрытие на 2026-10-23 (европейские марки, активные лоты): BMW 99,1%, Mercedes-Benz 99,9%,
Audi, Porsche, Mini, Land Rover, Volkswagen, Volvo — 99,5–100%; остаток — бейджи без двигателя
(BMW 2 Series Active Tourer F45) и единичные незнакомые слова.

## API

| Запрос | Ответ |
|---|---|
| `GET /api/catalog` | марки справочника с активными лотами |
| `GET /api/catalog/{makeId}` | модели, поколения, модификации, комплектации и `cells` — `[model, generation, modification, complectation, lots]` |
| `POST /api/search` | `refMakeId`, `refModelId`, `refGenerationIds[]`, `refModificationIds[]`, `refComplectationIds[]` |

Поиск фильтрует только по `ref_*`. Запрос, где машина названа текстом (ИИ-поиск, бот, сохранённые подписки, старые ссылки:
`make`, `model`, `generation`, `badge`, `trim`), переводится в id на входе — `App\Catalog\CatalogNames` из `SearchQuery::fromArray`:
- марка и модель — по имени без учёта регистра; модель без марки — если такое имя одно; точное имя раньше вхождения («Carnival» ≠ «Grand Carnival»);
- поколение — по коду, вместе с рестайлингами («DN8» → DN8 и «DN8 · The Edge»), также «Sonata (DN8)»;
- `trim` — комплектации марки в тексте (корейский — через словарь), остаток — код модификации («530e M 스포츠» → 530e + M Sport);
- название, которого справочник не знает, не находит ничего (`SearchQuery::matchesNothing`): подписка не превращается в «все машины».

Мини-приложение: каскад `js/catalog-filter.js` для всех марок. Старые «Модель / Серия / Комплектация» и `/api/filters/trims` убраны.
