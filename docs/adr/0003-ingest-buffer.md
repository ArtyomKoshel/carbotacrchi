# ADR-0003 · Передача данных через таблицу-буфер

**Контекст.** Сейчас лоты уходят HTTP-запросом в Laravel (`/api/internal/lots/upsert`), а часть данных парсер пишет в MySQL напрямую. HTTP привязывает сборщик к доступности сайта (деплой = потеря записей); два пути записи = нет одного владельца `lots`.

**Решение.**
- Сборщик пишет пачки в `collector.ingest_lots` (run_id, source, source_id, contract, payload JSON, content_hash, created_at). Это transactional outbox на общей СУБД.
- Ядро (очередь Laravel) забирает пачки, валидирует по схеме, делает идемпотентный upsert: одинаковый хэш — ничего не делает. Только ядро пишет `lots`, `lot_inspections`, `lot_changes`.
- `lot_changes` порождается доменными событиями ядра (LotListed, LotPriceChanged, LotDeactivated…) по сравнению «было/стало».
- Обработанные строки буфера удаляются по сроку хранения.

**Последствия.** Деплой сайта не теряет данные — буфер копится и разбирается после старта. Повторная доставка безопасна.
