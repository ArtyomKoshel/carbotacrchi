# ADR-0004 · Правила отбора считаются в конвейере до записи

**Контекст.** Сейчас upsert ставит `is_active=1`, а POST-фильтр через секунды ставит `0`: ~34 тыс. лотов «мигают» каждый прогон, ~65 тыс. мусорных строк `lot_changes` в сутки. Кроме того, превью правил в админке — вторая реализация логики.

**Решение.**
- PRE-правила — на данных списка, до запроса деталей (экономия прокси).
- POST-правила — на полном `CarLot` в памяти сборщика, до отправки в буфер. Для известных лотов с историей из прошлых прогонов POST можно посчитать и до запроса деталей.
- Вердикт (`selection: {passed, rule_ids, phase}`) — часть контракта; ядро ставит `is_active` один раз.
- Формат правил — общий набор фикстур, который проверяют и pytest, и PHPUnit (`parser/tests/fixtures/parse_filters_contract.json` → переедет в `contracts/`).

**Последствия.** Мигание невозможно по построению; одна точка истины для оценки правил.
