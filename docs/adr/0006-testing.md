# ADR-0006 · Стратегия тестирования

**Решение.**
- **Unit** (pytest, PHPUnit): чистая логика — маппинг, нормализация, правила, расчёт событий. Для нормализаторов — property-based (Hypothesis).
- **Эталон (characterization)**: записанные ответы Encar → вывод старого парсера сохраняется; новый адаптер обязан совпасть или каждое расхождение объяснено в фикстуре.
- **Контракт** (ADR-0002): схема CarLot, формат правил отбора и задач — общие фикстуры для обоих языков.
- **Интеграция**: репозитории и приём буфера — на настоящем MySQL (сервис-контейнер в CI, локальный docker), не sqlite.
- **E2E-дым**: сборщик на фикстурах → буфер → консьюмер ядра → `lots` в docker compose.
- **Без сети**: тесты не ходят во внешние API; живые проверки — отдельный маркер `live`, не запускаются по умолчанию.
- **Порог**: покрытие доменной части сборщика ≥ 90%, всего сборщика ≥ 80%; падение ниже — красный CI.
- **Статика**: ruff + mypy `--strict` (Python), Pint (PHP); всё в CI на каждый push.
