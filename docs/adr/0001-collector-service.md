# ADR-0001 · Сборщик — отдельный сервис со своей схемой MySQL

**Контекст.** Парсер (Python) и сайт (Laravel) живут в одном контейнере Railway под supervisord. Прогон Encar идёт 5–12,5 ч, деплой сайта его обрывает; том на веб-сервисе исключает zero-downtime. Скоро добавятся новые биржи. Команда маленькая; модульный монолит был бы дешевле, но владелец предпочитает явную границу сервиса ради порядка.

**Решение.**
- Два сервиса Railway из одного репозитория: `web` (Laravel: сайт, API, админка, ядро данных) и `collector` (Python: все биржи через адаптеры). Сервис на каждую биржу не делаем.
- Одна СУБД MySQL, но у сборщика своя схема `collector` и свой пользователь. В схему ядра (`railway`) сборщик не пишет; читает только через узкие каналы (ADR-0003).
- Каналы связи: команды — таблица `parse_jobs` (владелец ядро, сборщик меняет только статус/прогресс своих задач); настройки (правила отбора, площадки) — internal API ядра; данные — буфер (ADR-0003).

**Последствия.** Деплой сайта не трогает прогоны; сборщик масштабируется отдельно. Цена — контракт и права нужно поддерживать явно (ADR-0002, тесты в CI).
