# Готовность к источникам кроме Encar

> Проверено 2026-10-25 по коду ветки `feat/reference-catalog` (= прод `69a5fc2`) и прод-БД (только чтение).
> Связано: [catalog-migration.md](./catalog-migration.md), [cutover.md](./cutover.md), [13-catalog](../13-catalog.md).

## Вывод

**Каркас готов, конвейер — нет.** Контракт `carlot/1`, приём данных в ядре, очередь задач, сырой слой,
админка «Площадки» и фильтр источников в мини-приложении уже рассчитаны на несколько площадок.
Но сборщик умеет запускать только Encar (адаптер вшит в сервис), справочник читает только Encar
(`CatalogLinker::SOURCES = ['encar']`, один `EncarMatcher`), а несколько мест в ядре держат список `['encar']`
или `['encar', 'kbcha']` руками. Подключение второй площадки — это в первую очередь **адаптер сборщика**
и **матчер справочника** для её названий; остальное — правки по 1–20 строк.

Сейчас на проде только Encar: 140 356 активных и 69 852 неактивных лотов, `parse_jobs` только `encar`.
KBChacha выключен с апреля 2026 и пользователю не нужен (решение 2026-10-18); планируются другие площадки,
какие — пока не названо.

## Что сделать, чтобы подключить ещё одну площадку (по порядку)

| # | Работа | Размер |
|---|---|---|
| 1 | **Сборщик: интерфейс площадки.** Вынести из `runner.py`/`service.py` протокол «API + пайплайн + обход + replay», реестр адаптеров по `job.source`; Encar — первая реализация. Тесты сборщика должны остаться зелёными. | M (1–2 дня) |
| 2 | **Адаптер площадки** `adapters/<source>/`: API-клиент, обход (сегменты), маппинг в `CarLotV1`, история/проверка, golden-набор. Для KBChacha есть старый парсер на Python (`parser/parsers/kbcha/`, ~3,5 тыс. строк) — источник логики, не код для переноса. | L (3–5 дней на площадку) |
| 3 | **Ядро: убрать ручные списки.** `ParseFilter::SOURCES`, подписи в `FiltersController`, `Internal/LotsController`, расписание `lots:lifecycle` по каждому источнику, один список источников вместо трёх. | S (полдня) |
| 4 | **Опции площадки** → наши коды (`encar_option_catalog` или общий справочник опций), иначе фильтр опций не работает для её лотов. | M |
| 5 | **Справочник: матчер площадки.** Общий интерфейс `Matcher` (`match(array $variant): VariantMatch`), `CatalogLinker::SOURCES` из конфигурации, выбор матчера по `source`; файлы `resources/catalog/<source>/{make}.json` для её названий моделей; `coverage`/`reconcile` с `--source`. Цель — те же ≥ 99% разобранного. | L (2–4 дня + словари) |
| 6 | **Поиск и UI:** зарегистрировать провайдер, `sourceName`, проверить карточку (фото, история, проверка). | S |
| 7 | **Дедупликация** по VIN/номеру: связь лотов-дублей, в выдаче — одна машина с несколькими объявлениями. | M–L, можно после запуска |
| 8 | **Выкатка:** `COLLECTOR_SOURCES`, расписание в `parser_schedules`, проверка уведомлений и lifecycle на первых прогонах. | S |

## Риски

- **Lifecycle снимет лоты новой площадки** не сразу, а только если расписание вызовет его с её `--source`; иначе её снятые объявления останутся активными навсегда (п. 3).
- **Неполный прогон = ложное снятие.** На Encar это уже ловили (прогон #19, 404 через прокси). Для новой площадки нужен тот же учёт ошибок сегментов, прежде чем включать lifecycle.
- **Названия моделей другой площадки** не совпадут с деревом Encar; без матчера её лоты будут «вне справочника» и **пропадут из фильтров** (фильтр модели теперь только по `ref_*`).
- **Цена не в KRW** (если площадка не корейская) — запись отклоняется целиком; понадобится колонка валюты или конвертация.
- **Опции** другой площадки исказят `options_mask`, если их коды пересекутся с кодами Encar.
- **Дубли** одной машины на двух площадках удвоят выдачу и счётчики фильтров.
- **Прокси**: общий аккаунт FloppyData и лимиты — две площадки параллельно могут мешать друг другу (уже есть правило: не обходить дерево Encar во время полного прогона).

## Рекомендация

1. **Сначала доделать Encar-хвосты, которые влияют на любую площадку:** удаление старой дороги (релиз 2), учёт ошибок сегментов в полном прогоне (иначе lifecycle опасен), lifecycle по каждому источнику в расписании.
2. **Затем п. 1 и 3 без новой площадки** — интерфейс площадки в сборщике и один список источников в ядре. Это рефакторинг, проверяемый тестами Encar, без внешних рисков.
3. **Какую площадку первой** — решать бизнесу. KBChacha пользователю не нужен (2026-10-18). Если выбор между корейскими площадками, выгоднее та, у которой есть открытый JSON-API и дерево марок/моделей (как iNav у Encar): матчер справочника тогда строится тем же генератором. Площадка не на корейском языке потребует ещё и словарей (п. 5) и, возможно, валюты.
