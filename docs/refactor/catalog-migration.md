# Переход на справочник: план

> Цель: одна дорога **Encar → справочник → фильтры и экран**, без ИИ-переводов посередине;
> справочник — все марки и модели, которые знает Encar; ни одна машина не теряется в фильтрах.
> Справочник — [13-catalog](../13-catalog.md).

Работаем локально (дамп прода, прокси через `railway run`) до пуша в `main`. Всё, что удаляет
данные на проде, — только после явного «да» с превью количества строк.

---

## Принципы

1. **Ничего не додумываем** (память `feedback-no-guessed-specs`): привод, топливо, поколение — только из
   того, что Encar указал. Неизвестное — пусто → ручная разметка.
2. **Факты о модели — от площадки.** Годы поколения берём из `ModelStartDate` / `ModelEndDate`, которые
   Encar отдаёт у каждой модели, а не из памяти; код модели Encar (`Code`) — стабильный ключ соответствия.
3. **Переводы — только проверенные.** Название в справочнике имеет происхождение: `official` (как пишет
   производитель, сверено), `encar` (как пишет Encar латиницей), `draft` (нужна проверка — видно в админке).
   ИИ-переводы без проверки в справочник не попадают.
4. **Каждый шаг доказывается сверкой** — числа, а не «должно работать».

---

## Этап 0 · Полное дерево Encar

- `analysis/scrape_encar_inav_tree.py` через прокси: все марки (CarType Y и N) → ModelGroup → Model →
  BadgeGroup → Badge → BadgeDetail, **включая узлы с 0 объявлений**, с метаданными модели (код, даты
  выпуска) и кодами бейджей. Результат — `analysis/data/encar_tree_YYYY-MM.json` (не в git: это трафик Encar).
- Критерий: дерево покрывает все варианты активных лотов дампа (каждая пара model/badge лота есть в дереве).

## Этап 1 · Справочник из дерева — все марки

- Генератор `catalog:build-from-tree` (только черновик в `resources/catalog`, правится руками):
  - модели = ModelGroup Encar; поколения = модели Encar, годы — даты Encar; код кузова — из названия
    («(DN8)», «W213») или подтверждённый вручную; рестайлинг и гибрид Encar держит отдельными моделями —
    у нас это поколение с пометкой (`facelift`, силовая установка), чтобы фильтр мог показать и то, и другое;
  - корейские марки: BadgeGroup = топливо + объём («가솔린 2000cc»), Badge = двигатель, BadgeDetail =
    комплектация — правила для них (`KoreanRules`) читают ровно это;
  - модификации и комплектации заранее из дерева (не только из лотов): фильтр знает весь список.
- Сохраняем ручную работу по 18 европейским маркам: генератор дополняет, не перетирает; расхождения
  (годы, лишние/недостающие поколения) — отчётом.
- Критерий: `catalog:validate` чист по файлам; по данным — расхождения только там, где поколение назвал сам Encar.

## Этап 2 · Нормальные переводы

- Названия моделей и комплектаций — в справочнике (`name`, при надобности `name_ru`) с происхождением.
- Корейские слова (`encar/tokens.json`): официальные латинские названия комплектаций (인스퍼레이션 →
  Inspiration, 캘리그래피 → Calligraphy …) сверяем с англоязычными материалами производителей; спорные — `draft`.
- Админка: страница справочника с фильтром «черновики», правка названия переносится на все лоты сразу.
- `translations` после этапа 5 остаётся только для цветов.
- Критерий: в справочнике 0 названий `draft` у моделей с активными лотами; ни одного корейского символа в
  названиях моделей, поколений, модификаций, комплектаций.

## Этап 3 · Сверка «не теряем ни одной машины»

Команда `catalog:reconcile` (только чтение), запускается после каждого remap и по расписанию:

| Проверка | Должно быть |
|---|---|
| Активные лоты Encar без `ref_variant_id` | 0 |
| Лоты марки справочника = сумма ячеек `/api/catalog/{make}` (+ «не разобрано») | равно |
| Для каждой ячейки модель/поколение/модификация/комплектация: `POST /api/search` count = COUNT в БД | равно |
| Наши активные лоты по модели Encar против счётчиков Encar (живой iNav через прокси) | расхождение ≤ задержки парсинга, отчёт по моделям |
| Случайная выборка N лотов на марку: страница Encar ↔ место в справочнике | таблица для глаз |
| Лоты, чей год вне годов поколения | только где поколение назвал Encar |

- В фильтре видны и неразобранные: «Поколение не указано (N)», «Модификация не указана (N)», «Прочие модели (N)» —
  выбор модели или поколения никогда не прячет машину молча.

## Этап 4 · Все потребители на справочник

- Фильтры мини-приложения — каскад для всех марок; старые «Серия / Комплектация» уходят.
- ИИ-поиск и бот (`ChatSearchService`, `TelegramBot`): понимают «BMW 5 G60», ищут по `ref_*`.
- Карточка клиенту (`ClientLotCard`), уведомления подписок, админка (лоты, изменения), `lots_archive` — названия из справочника.
- Сохранённые подписки со строками марки/модели — один раз переводятся на id справочника (с отчётом).

## Этап 5 · Выключить старую дорогу

- Убрать из расписания `lots:normalize-from-catalog`; удалить `translate:run`, `lots:ai-model-en-backfill`,
  `catalog:import-*`, `catalog:build-badges`, `/api/filters/context`, `/api/filters/trims`, страницу «Проверка переводов».
- Таблицы `catalog_model_trims`, `catalog_badges`, `catalog_drive_tokens`, `catalog_models` и все `translations`,
  кроме цветов, — **удаление на проде только после «да»**.
- Колонки `lots.*_en`; вернуть в `lots.trim` значение Encar из `raw_data.pre_norm` (46 808 лотов с копией бейджа) —
  **после «да»**, с превью.

## Этап 6 · Выкатка

1. Миграции (таблицы `ref_*`, колонки, индексы) — укладываются в 30 с healthcheck (замерено: 2–3 с).
2. `catalog:remap` на Railway (≈2 мин на локальном дампе).
3. `catalog:validate`, `catalog:reconcile` — числа в отчёт.
4. Мини-приложение с каскадом для всех марок.
5. Только потом — этап 5 на проде.
